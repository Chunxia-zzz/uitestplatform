## User Scenarios & Testing *(mandatory)*

### User Story 1 - Mock 网络接口与检索网络响应 (Priority: P1)

测试工程师在编写导出、第三方依赖、异常注入类用例时，被测页面的数据来自后端接口，无法在 UI 层构造。用户希望：在用例步骤里声明"对匹配某地址模式的接口，返回我指定的内容（或直接中断）"，此后页面加载到的就是 mock 数据；验证完毕后解除 mock。用户还希望在等待/断言时能查询"执行期间是否发生过匹配某模式的网络响应、其状态码是什么"，用于确认前端确实发过某个请求。

**Why this priority**: 接口依赖是 UI 自动化抖动与不可测（无法构造异常/空数据场景）的首要来源；mock 能力直接决定"写不写得出来"这类用例，价值最高。

**Independent Test**: 建一条用例：打开页面 → 对 `/api/demo` 设置 mock（返回固定 JSON）→ 触发页面请求 → 断言页面出现 mock 内容 → 解除 mock → 再触发 → 断言恢复真实内容。全程可独立执行验收。

**Acceptance Scenarios**:

1. **Given** 用例中某步骤对地址模式 P 声明了 mock（状态码 S、响应体 B），**When** 页面此后发起匹配 P 的请求，**Then** 收到的响应状态码为 S、响应体为 B，且该请求不真实到达后端。
2. **Given** 某步骤声明了"中断"型 mock，**When** 页面发起匹配请求，**Then** 请求失败（网络层错误），页面呈现失败态。
3. **Given** mock 已生效，**When** 用户用"等待/检索网络响应"动作查询模式 P（限定自某参考时间起），**Then** 能取到匹配的响应记录（地址、状态码），并在超时窗口内轮询等待新匹配。
4. **Given** 用例 A 设置了 mock 且未显式解除，**When** 同一次执行的用例 B 开始执行，**Then** 用例 B 不再受该 mock 影响（用例边界自动清理）。
5. **Given** 用户对从未声明过的模式执行"解除 mock"，**Then** 得到明确的失败信息（而非静默成功）。

### User Story 2 - 下载文件保存为产物并可断言 (Priority: P2)

测试工程师要测"导出报表/下载附件"类功能：点击页面按钮触发浏览器下载。此前平台无法处理下载，用例只能止步于"点了按钮"。用户希望：步骤绑定的元素被点击后，平台接管浏览器下载行为，把文件保存下来，作为本次执行的产物出现在报告与产物列表中；文件名可用于后续断言。

**Why this priority**: 下载是常见业务功能，此前完全无法覆盖；但出现频率低于接口依赖，故列 P2。

**Independent Test**: 在 fixture 页面放一个下载链接，用例：点击该链接 → 断言产生下载产物 → 通过产物下载接口取回文件内容与源文件一致。

**Acceptance Scenarios**:

1. **Given** 步骤绑定触发下载的元素并执行下载动作，**When** 浏览器产生下载，**Then** 平台把文件保存为本次执行的产物，产物列表与报告中可见（类型为"下载"）。
2. **Given** 下载已完成并登记产物，**When** 用户通过产物下载接口取回，**Then** 拿到的文件与浏览器实际下载的一致（文件名与内容）。
3. **Given** 步骤绑定的元素被点击但始终没有产生下载，**When** 超出该步骤的超时窗口，**Then** 该步骤按超时失败并给出明确信息，执行器正常继续后续流程。

### User Story 3 - iframe 按元素进入 (Priority: P3)

被测页面存在业务 iframe，但 iframe 在页面中的出现顺序不固定（广告位、懒加载、条件渲染都会改变顺序）。用户此前只能"按第 N 个 iframe 进入"，顺序一变用例就错。用户希望：给步骤绑定"iframe 元素本身"（用既有定位符体系描述这个 iframe），动作直接进入**这个** iframe；退出语义保持不变（无参弹栈）。

**Why this priority**: 解决真实痛点（动态顺序 iframe），但触发频率依赖具体业务页面，列 P3。

**Independent Test**: fixture 页面放两个内容不同的 iframe（顺序可交换），用例绑定"内容为结算面板的 iframe"元素的定位符进入 → 对其内部元素断言；再验证无参步骤退出后回到主文档。

**Acceptance Scenarios**:

1. **Given** 步骤绑定了一个 iframe 元素（定位符指向该 iframe 节点），**When** 执行进入动作，**Then** 后续元素操作都发生在该 iframe 内部，与 iframe 在页面中的出现顺序无关。
2. **Given** 当前已通过元素进入某 iframe，**When** 执行无参的进入/退出动作，**Then** 弹栈回到上一层（既有语义不变）。
3. **Given** 步骤同时绑定了 iframe 元素又给了顺序 index，**When** 保存或执行该步骤，**Then** 被拒绝并提示二选一（不允许歧义）。
4. **Given** 绑定元素的定位符命中的不是 iframe 节点，**When** 执行进入动作，**Then** 该步骤失败并给出明确信息（命中了什么、期望什么）。

### User Story 4 - 执行级共享变量 (Priority: P3)

用例集（套件）一次执行多个用例时，用户希望某些数据只算/取一次、后续用例复用——例如登录后取到的 token、第一条用例从页面读到的单号。用户希望：设置变量时可显式声明"执行级"；读取变量时用例级优先、执行级兜底；不声明时行为与现状完全一致（变量只在用例内可见）。

**Why this priority**: 提升套件场景的数据复用效率，但现有"写死参数"可绕过，列 P3。

**Independent Test**: 一条套件含 A、B 两用例：A 用"执行级"作用域设置变量 v；B 的步骤引用 `${v}` 能取到值。对照组：另一变量不用执行级作用域设置，B 读不到。

**Acceptance Scenarios**:

1. **Given** 用例 A 以"执行级"作用域设置变量 v，**When** 同一次执行的用例 B 渲染 `${v}`，**Then** 取到 A 设置的值。
2. **Given** 用例 B 自己也以"用例级"设置了同名变量 v，**When** B 渲染 `${v}`，**Then** 取 B 自己的值（用例级优先）。
3. **Given** 用户不声明作用域（既有用例不改），**When** 执行，**Then** 行为与现状完全一致：变量仅本用例可见，下个用例读不到。
4. **Given** 执行已结束，**When** 下一次执行开始，**Then** 上一次执行的所有变量（含执行级）全部不可见。

### Edge Cases

- mock 模式与解除模式不一致（含通配符写法差异）→ 解除时按"完全一致的声明"匹配，匹配不到报明确错误（见 US1 场景 5）。
- 同一执行内多次对同一模式重复声明 mock → 后声明覆盖先声明（后写生效），解除一次即清。
- 下载触发后产生多个文件 → 只接管并保存第一个，其余忽略；文档注明限制。
- iframe 元素定位符命中多个节点 → 沿用回退链语义取第一条命中，命中 0 条报错。
- 执行级变量名与用例级变量名相同 → 用例级优先（US4 场景 2），报告/日志不隐藏该事实。
- mock 声明在用例中途、页面已发出的请求 → 不追溯，只影响声明之后的请求。
- 等待/检索响应的窗口内没有任何匹配 → 超时失败并附已收集的近邻请求摘要（便于排查模式写错）。

## Requirements *(mandatory)*

### Functional Requirements

**网络 mock 与响应检索（GAP-09）**

- **FR-001**: 系统 MUST 提供"声明 mock"动作：按地址模式匹配请求，返回指定状态码与响应体；响应体支持文本与 JSON 两种写法。
- **FR-002**: 系统 MUST 提供"中断请求"型 mock：匹配请求直接失败，不返回任何响应体。
- **FR-003**: 系统 MUST 提供"解除 mock"动作：按声明时的地址模式解除；解除不存在的声明 MUST 报明确错误。
- **FR-004**: 系统 MUST 保证 mock 的影响范围限于当前执行会话，且**用例边界自动清理**（不需要用例作者显式解除也不泄漏到后续用例）。
- **FR-005**: 系统 MUST 提供"等待/检索网络响应"动作：在步骤超时窗口内轮询，返回自参考时间以来匹配地址模式的响应记录（含状态码），支持把结果存入变量供断言。
- **FR-006**: 系统 MUST 记录执行期间的网络响应供 FR-005 检索；检索不到时 MUST 附近邻请求摘要辅助排查。

**下载处理（GAP-10）**

- **FR-007**: 系统 MUST 提供"下载"动作：点击步骤绑定的元素并接管浏览器下载，把文件保存为本次执行的产物。
- **FR-008**: 下载产物 MUST 出现在产物列表与报告里（新增"下载"产物类型），且可通过既有产物接口取回；API 不得暴露服务器路径。
- **FR-009**: 下载动作 MUST 支持把保存后的文件名写入变量供后续断言；未产生下载时 MUST 在超时窗口后失败。

**iframe 按元素（GAP-12）**

- **FR-010**: 进入/退出 iframe 动作 MUST 新增"按元素进入"形态：步骤绑定 iframe 元素即进入该 iframe；顺序 index 与元素绑定 MUST 互斥（校验拒绝）。
- **FR-011**: 无参弹栈语义 MUST 保持不变（D12 冻结语义扩展，非破坏）；绑定元素但命中非 iframe 节点 MUST 明确报错。

**执行级变量（GAP-13）**

- **FR-012**: 设置变量动作 MUST 支持可选作用域参数：`case`（默认）与 `execution`；不声明时行为与现状完全一致（向后兼容）。
- **FR-013**: 变量读取 MUST 按"用例级优先、执行级兜底"解析；执行级变量生命周期限于单次执行，执行结束即失效。
- **FR-014**: 上述新动作 MUST 全部进入动作字典与能力矩阵（声明 vs 实现强校验沿用现状）；字典总数由 51 增至 55；set_variable / switch_to_iframe 的变更 MUST 在设计文档变更记录留痕。

### Key Entities *(include if feature involves data)*

- **动作字典**：新增 4 条动作声明（声明 mock / 解除 mock / 等待检索响应 / 下载），`switch_to_iframe`、`set_variable` 参数扩展；能力矩阵同步。
- **执行产物**：新增"下载"产物类型；保存路径遵循产物目录组织（`exec-{id}` 下），登记与取回沿用既有产物机制（归属校验、不暴露服务器路径）。
- **执行级变量存储**：随执行存在、执行结束销毁，不落库、不跨执行。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对指定接口设置 mock 后，页面读到的内容与 mock 声明一致、与真实接口无关；解除后恢复真实内容（US1 场景 1 全链路可复现）。
- **SC-002**: 用例 A 设置的 mock 对同次执行的用例 B 零影响（自动清理可验证）。
- **SC-003**: 触发下载的用例执行后，产物列表出现"下载"产物，且通过产物接口取回的文件与源文件一致。
- **SC-004**: 绑定 iframe 元素的用例在 iframe 出现顺序被调换后仍稳定通过（顺序无关性可验证）。
- **SC-005**: 套件用例 B 能取到用例 A 的执行级变量；未声明作用域的既有用例行为逐字节不变。
- **SC-006**: 全量既有测试与五份 Web 冒烟保持全绿（零回归）；本批次新增用例与冒烟脚本覆盖上述全部验收场景。

## Assumptions

- mock 作用域为**单次执行的浏览器会话**：不同执行之间互不可见；同一执行串行复用会话（与现状一致）。
- mock 不追溯已发出的请求；匹配模式用业界通用的通配写法（如 `**/api/**`），具体语法在 plan 阶段定。
- 下载文件沿用现有产物生命周期与清理策略，不额外引入持久存储。
- 执行级变量不提供其他写入路径——所有动作的 `output_var` 输出一律落在用例级（保持既有语义），执行级只能通过 `set_variable(scope=execution)` 显式写入。
- iframe 按元素进入只处理**同文档** iframe；跨文档嵌套（iframe 里再进 iframe）沿用弹栈叠加，不新增语义。
- 本批次仅覆盖 Web 端；移动端不受影响、不实现对应动作（mock/下载/iframe 元素语义为浏览器会话概念）。
